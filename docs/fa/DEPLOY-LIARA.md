# استقرار روی لیارا

این راهنما سرویس‌هایی را که باید در لیارا بسازید و ترتیب راه‌اندازی را می‌گوید. لیارا فایل Docker Compose را اجرا نمی‌کند؛ هر سرویس یک برنامهٔ جدا در یک شبکهٔ خصوصی است. جزئیات شبکه و دیسک: [شبکه خصوصی](https://docs.liara.ir/paas/details/private-network/) و [دیسک](https://docs.liara.ir/paas/docker/how-tos/use-disk/).

## ۱. شبکه خصوصی

در ساخت اولین سرویس یک شبکهٔ خصوصی تازه بسازید، مثلاً `owu-net`. برنامه و دیتابیس هر دو باید عضو همین شبکه باشند. بعد از ساخت، شبکه را نمی‌توان عوض کرد.

## ۲. PostgreSQL

- نوع: PostgreSQL نسخه ۱۶ یا ۱۷
- همان شبکهٔ `owu-net`
- در زمان ساخت، افزونه **Pgvector** را روشن کنید
- پلن ۱ تا ۲ گیگابایت رم کافی است (حدود ۱۰ هزار قطعهٔ ۱۰۲۴بعدی نزدیک ۴۰ مگابایت است)
- دسترسی عمومی را خاموش کنید

لیارا ایندکس HNSW را ندارد. ایمیج با `PGVECTOR_INDEX_METHOD=ivfflat` بالا می‌آید. اگر برنامه در شروع خطای افزونه داد، یک بار با کاربر دیتابیس این دستور را بزنید:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## ۳. برنامه Docker

- پلتفرم: Docker
- شناسه پیشنهادی: `owu`
- شبکه: `owu-net`
- پورت: `8080`
- پلن: ۸ گیگابایت رم و ۴ هسته (پلن اورانوس در جدول قیمت پلتفرم). مدل `intfloat/multilingual-e5-large` داخل همین کانتینر و روی CPU اجرا می‌شود و به این حافظه نیاز دارد.
- دیسک: شناسه `data`، مسیر `/app/backend/data`، اندازه ۱۰ تا ۲۰ گیگابایت. مسیر را مطلق بدهید. وزن مدل‌ها بیرون این مسیر، داخل ایمیج است و با دیسک پوشیده نمی‌شوند.

### ساخت ایمیج

پوش به برنچ `custom/main` گردش‌کار `.github/workflows/build-image.yml` را اجرا می‌کند و ایمیج `linux/amd64` را در GHCR عمومی می‌گذارد. بستهٔ GHCR را Public کنید تا لیارا بدون توکن آن را بکشد.

در `deploy/liara/liara.json` مقدار `image` را با آدرس واقعی عوض کنید، سپس:

```bash
cd deploy/liara
liara deploy --platform=docker
```

استقرار خودکار وقتی انجام می‌شود که متغیر مخزن `LIARA_DEPLOY` برابر `true` باشد و سکرت `LIARA_TOKEN` ست شده باشد.

موقعیت بیلد لیارا برای این مسیر لازم نیست، چون بیلد روی GitHub انجام می‌شود. اگر بخواهید خود لیارا سورس را بیلد کند، حافظهٔ بیلد فرانت‌اند ممکن است کم بیاید؛ مسیر GHCR همین را دور می‌زند.

### متغیرهای محیطی

نمونه در `deploy/liara/env.example` است. این‌ها را حتماً بگذارید:

- `WEBUI_URL` آدرس نهایی `https://...`
- `WEBUI_SECRET_KEY` یک رشتهٔ تصادفی ثابت
- `WEBUI_NAME` نام برند
- `DATABASE_URL` و `PGVECTOR_DB_URL` از بخش «نحوه اتصال» دیتابیس، با میزبان شبکهٔ خصوصی
- `OPENAI_API_BASE_URL` و `OPENAI_API_KEY` برای مدل زبانی (سرویس هوش مصنوعی لیارا یا هر API سازگار با OpenAI)
- `TASK_MODEL_EXTERNAL` یک مدل ارزان برای تولید عنوان و کوئری بازیابی. اگر این تأخیر را نمی‌خواهید: `ENABLE_RETRIEVAL_QUERY_GENERATION=false`

`UVICORN_WORKERS=1` بماند. چند ورکر مدل امبدینگ را چند بار در حافظه می‌آورد.

اولین ایندکس حدود ۲۵۰۰ صفحه روی CPU ممکن است یک تا دو ساعت طول بکشد. خودِ پرسش، بعد از ایندکس، باید در حد یک ثانیه برای بردارسازی تمام شود. بردارهای قبلی که با `all-MiniLM-L6-v2` ساخته شده‌اند با این مدل سازگار نیستند و باید پایگاه دانش دوباره ساخته شود.

### بعد از بالا آمدن

1. حساب مدیر را بسازید.
2. زبان پیش‌فرض فارسی است و چیدمان راست‌چین می‌شود.
3. در مدیریت، تنظیمات، بخش برند: نام، شعار و لوگو را بگذارید. فایل‌ها روی دیسک `data` می‌مانند.
4. پیشنهادهای صفحهٔ اول: مدیریت، مدل‌ها، پیش‌فرض مدل‌ها. برای فارسی زبان `fa-IR` را انتخاب کنید. اگر خالی بماند، چهار پیشنهاد فارسی داخل ایمیج استفاده می‌شود.
5. یک اتصال OpenAI با همان آدرس و کلید API بسازید و مدل را انتخاب کنید.
6. یک پایگاه دانش بسازید و یک سند ورد آزمایشی آپلود کنید، بعد با `#` همان دانش را به گفتگو وصل کنید.

## چرا سرعت و دقت بهتر می‌شود

- امبدینگ چندزبانهٔ `multilingual-e5-large` به‌جای مدل فقط‌انگلیسی پیش‌فرض
- پیشوندهای اجباری `query: ` و `passage: `
- جستجوی ترکیبی برداری و BM25
- ده قطعه به‌جای سه قطعه
- PostgreSQL با ایندکس `ivfflat` به‌جای Chroma داخل کانتینر
- قالب پاسخ که اگر جواب در سند نباشد صریح بگوید و از دانش عمومی پر نکند

Reranker اختیاری `BAAI/bge-reranker-v2-m3` را می‌توان با build-arg زیر داخل ایمیج گذاشت. روی CPU حافظهٔ اضافه می‌خواهد:

```bash
docker build --build-arg USE_RERANKING_MODEL=BAAI/bge-reranker-v2-m3 .
```

و در محیط: `RAG_RERANKING_MODEL=BAAI/bge-reranker-v2-m3`.

## فاز ۲: RAGFlow

اگر بعد از فاز بالا هنوز دقت سندهای خیلی بزرگ کافی نبود، RAGFlow را جدا بگذارید. روی پلتفرم معمولی لیارا جا نمی‌شود (Elasticsearch، MySQL، Redis و MinIO، دست‌کم ۱۶ گیگابایت رم). آن را روی یک سرور مجازی لیارا با حداقل ۱۶ گیگابایت رم اجرا کنید و از Open WebUI با یک سرور ابزار MCP از نوع Streamable HTTP وصل کنید. بعد یک مدل بسازید که آن ابزار را روشن داشته باشد. این همان مسیری است که در مقالهٔ همکاران سیستم آمده، نه تغییر کد بازیابی داخلی.

## به‌روزرسانی از نسخهٔ بالادست

ریموت `upstream` به `https://github.com/open-webui/open-webui.git` اشاره می‌کند. تاریخچهٔ محلی کم‌عمق است. برای گرفتن نسخهٔ بعد:

```bash
git fetch --unshallow upstream
git fetch upstream tag vX.Y.Z
git merge vX.Y.Z
```

تعارض‌ها بیشتر در `config.py`، `env.py`، `src/lib/i18n` و کلاس‌های چیدمان خواهد بود.
